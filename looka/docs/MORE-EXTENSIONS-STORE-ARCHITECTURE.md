# Looka「更多、扩展与商店」产品架构规格

> 版本：v1.0
> 日期：2026-08-24
> 状态：已确认产品方向，尚未开发、尚未上线
> 范围：Android App、网页、服务端、账号权益、支付、同步、隐私与多语言
> 执行边界：本文只定义目标架构，不代表扩展、商店、生活账本或支付入口当前已经可用。

---

## 一、文档地位与使用方法

### 1.1 本文负责什么

本文是以下未来能力的目标规格：

1. “更多”页的信息架构与交互合同；
2. “扩展”与“扩展商店”的用户心智；
3. 扩展清单、启用状态、入口注册、权限和数据生命周期；
4. 永久权益、平台支付、恢复购买与退款撤销；
5. 首个功能扩展“生活账本”的接入方式；
6. Android、网页和服务端的职责边界；
7. 首期官方扩展商店与未来创作者市场的边界。

### 1.2 真值优先级

发生冲突时按以下顺序处理：

1. 当前代码和线上真实能力决定“今天用户能用什么”；
2. docs/COPY-AND-ENTITLEMENT-SPEC.md 决定当前可对外承诺的权益；
3. 本文决定未来“更多、扩展与商店”的目标产品架构；
4. docs/BOOKKEEPING-AI-RECEIPT-PLAN.md 决定生活账本的数据、OCR 和 AI 细节；
5. FEATURE-PLAN、ROADMAP、SUBSCRIPTION 和历史讨论只解释演变过程。

本文不把规划中的扩展写成当前权益，也不自动修改 Free、Pro 或鹿角现行规则。

### 1.3 对旧方案的修订

本文保留以下产品决定：

- 生活账本是独立增值模块；
- 一次取得、永久拥有，不因 Pro 到期失效；
- 已有账目始终可以查看、修改、导出和删除；
- 手工记账、基础统计、同步、导入导出和本机 OCR 不按次消耗鹿角；
- AI 整理等增量服务可以按次消耗鹿角。

本文修订以下旧结论：

- “所有平台统一用 500 枚鹿角解锁”不再是跨平台实施合同；
- 500 枚鹿角只保留为历史产品价值候选，不是已上线价格，也不是 iOS 的既定结算方式；
- 永久权益通过平台结算适配器取得，具体支付方式必须在各平台上线前单独完成合规核验。

## 二、产品结论

### 2.1 三个空间各做一件事

| 空间 | 核心职责 | 不承担 |
| --- | --- | --- |
| 更多 | 管理账号、偏好、数据、安全、扩展和帮助 | 不承担高频记账，不堆促销内容 |
| 扩展 | 管理已经拥有或可以启用的能力 | 不承担商品发现和营销 |
| 扩展商店 | 发现、了解、取得和恢复扩展权益 | 不成为日常使用入口 |

扩展启用后，真正的使用入口回到日历、中央“＋”、搜索和相关内容页面。用户不需要每天经过“更多”或商店才能使用生活账本。

### 2.2 用户术语

| 内部概念 | 用户界面用词 | 说明 |
| --- | --- | --- |
| Plugin | 扩展 | 不向普通用户展示技术术语“插件” |
| Plugin manager | 我的扩展 | 管理启用、入口、数据和权限 |
| Plugin store | 扩展商店 | 发现与取得新能力 |
| Install | 启用 | 首期功能代码随 App 发布，不制造“下载安装代码”的错觉 |
| Download | 下载 | 只用于确实需要下载的主题、贴纸或离线资源 |
| Non-consumable entitlement | 永久解锁 | 一次取得，长期有效 |
| Restore purchases | 恢复购买 | 只恢复已取得权益，不重复收费 |

小鹿 AI 是 Looka 的系统级助手，首期不作为普通扩展出售。它可以调用扩展提供的受控能力，但其隐私授权、鹿角用量和失败回退仍由统一 AI 合同管理。

## 三、现状与根因

### 3.1 Android 现状

当前 Android 的 MoreScreen.kt 已经形成六组语义列表：

- 我：账号与同步、订阅·鹿角；
- 小鹿：小鹿 AI；
- 外观：主题；
- 设置：日历设置、提醒自检、语言；
- 数据：备份与维护；
- 帮助：关于 Looka。

结论：Android 的骨架已经成熟，不需要再次推翻成宫格。下一步是把品牌区改成有状态的账户卡，补齐“扩展、数据与隐私、帮助与反馈”的入口合同。

### 3.2 网页现状

当前 server/public/index.html 的“更多”仍是一个未分组的长列表，混放 AI、日记、主题、昵称、同步、搜索、导入导出、查重、兑换、Pro、法律文本和退出登录。

结论：网页需要与 Android 对齐语义分组，但不能直接删除网页特有入口。任何入口迁移前必须确认新的可达路径已经存在：

- 日记在网页获得新的原生入口前，旧入口暂时保留；
- 搜索在网页获得页首或全局入口前，旧入口暂时保留；
- 隐私政策、用户协议和退出登录必须在账号或帮助深页中保留可达；
- 迁移采用“先增加新入口、验证可达、再删除旧入口”的顺序。

### 3.3 根因

“更多”页不断变长的根因不是行高或滚动距离，而是三种对象被放在了同一层：

1. 产品设置；
2. 高频内容操作；
3. 商品发现与购买。

本规格通过分层解决：更多负责管理，扩展负责能力，商店负责购买，高频操作返回内容场景。

### 4.2 账户状态卡

账户卡代替当前只展示品牌口号的大块品牌区。它不是广告位。

显示规则：

| 状态 | 主标题 | 副信息 | 操作 |
| --- | --- | --- | --- |
| 未登录 | 登录 Looka | 同步与恢复你的记录 | 进入登录 |
| 已登录、同步正常 | 用户昵称 | Free 或 Pro · 已同步 | 进入账号 |

同步失败不能只显示红点。副信息必须说明用户数据是否仍保存在本机。

| 设置 | 日历与显示 | 可选摘要 | 日历设置 |

### 4.4 不放在根页的内容

- 搜索属于内容操作，不属于设置；
- 日记属于内容对象，不属于设置；
- 立即同步属于账号详情中的操作，不应长期占一行；
- 导入、导出、查重和冲突记录收进对应数据深页；
- 隐私政策和用户协议进入“关于 Looka”或“隐私设置”，但必须保持可达；
- 退出登录进入“账号与同步”底部；
- Pro 不使用大横幅、倒计时或弹窗常驻抢占“更多”。

网页旧入口只有在替代路径真实存在并通过浏览器验证后才能移除。

## 五、导航与回退合同

### 5.1 顶层规则

- “更多”保留在当前四个顶层标签之一；
- 商店和生活账本首期不增加新的底部标签；
- 从其他顶层标签切回“更多”时，恢复原滚动位置；
- 从“更多”进入二级页使用标准前进导航；
- 返回时回到原分组与滚动锚点，不回到页首；
- 购买、登录或系统权限页面返回后，恢复发起操作前的商品或设置上下文。

### 5.2 扩展路由

建议的语义路由：

| 路由 | 含义 |
| --- | --- |
| more | 更多根页 |
| extensions | 我的扩展 |
| extensions/store | 扩展商店 |
| extensions/{extensionId} | 已拥有扩展详情 |
| extensions/store/{extensionId} | 商店详情 |
| extensions/{extensionId}/settings | 扩展设置 |
| finance | 生活账本首页 |
| finance/new | 记一笔 |
| finance/receipt | 扫票据 |

Android 可以使用内部 NavHost 路由；网页使用等价的 History 路由或稳定 hash。不同端的 URL 形式可以不同，语义和回退结果必须一致。

### 5.3 深链接回退

| 场景 | 回退 |
| --- | --- |
| 未拥有扩展却打开功能深链 | 进入商店详情，说明需要永久解锁 |
| 已拥有但未启用 | 进入扩展详情，提供“启用” |
| 当前平台不支持 | 展示兼容性说明，不进入空白页 |
| App 版本过低 | 展示所需版本与更新入口 |
| 商品已下架但用户已拥有 | 允许打开现有功能与数据，不显示购买 |
| 商店服务离线 | 已拥有扩展照常使用；商店显示缓存与重试 |
| 用户取消购买 | 回到原商品详情，页面与滚动位置不丢失 |

## 六、扩展中心

### 6.1 页面结构

    ‹ 更多                    扩展

    [ 已启用 ]    [ 商店 ]

    生活账本
    记录日常收支与生活轨迹
    已启用                         ›

分段控件记住用户上次选择，但从“我的扩展”进入时默认打开“已启用”，从“扩展商店”进入时默认打开“商店”。

### 6.2 已启用列表

每个扩展显示：

- 图标、名称和一句用途；
- 已启用、未启用、需要更新或当前平台不可用；
- “打开”与“管理”；
- 必要时显示资源下载进度；
- 不显示营销折扣和价格。

空状态：

> 还没有启用扩展。
> 你可以从扩展商店选择适合自己的工具。

### 6.3 扩展详情

扩展详情包含：

1. 名称、版本和开发者；
2. 当前权益与启用状态；
3. 它会出现在哪里；
4. 数据与权限；
5. 设置；
6. 导出扩展数据；
7. 停用扩展；
8. 删除扩展数据。

“停用”和“删除数据”必须分离：

- 停用只隐藏入口并停止新建，不删除历史数据；
- 删除数据是单独的危险操作，需要说明范围、二次确认和可恢复策略；
- 卸载 App、退出 Pro 或扩展下架都不得自动删除扩展数据。

## 七、扩展商店

### 7.1 首期定位

首期商店只提供 Looka 官方扩展和官方内容包，是一个经过策划的目录，不是开放市场。

首期不开放：

- 第三方上传可执行代码；
- 用户自行发布扩展；
- 创作者分账；
- 未审核的主题、贴纸或模板；
- 通过网页密钥、二维码或兑换码绕过平台数字内容结算。

### 7.2 商店首页

推荐顺序：

1. 一个精选扩展大卡；
2. “适合你的记录方式”；
3. 分类；
4. 全部扩展；
5. 已购项目；
6. 恢复购买与购买帮助。

移动端不使用密集三列商品宫格。精选区一次只突出一个主商品，避免把安静手帐变成促销货架。

### 7.3 商品卡

商品卡只显示做决定所需的信息：

- 图标；
- 名称；
- 一句结果导向描述；
- 类型，例如“功能扩展”或“主题包”；
- 真实价格或“已拥有”；
- 必要的兼容性提示。

首期没有真实数据时，不显示评分、销量、倒计时、原价划线或“大家都在买”。

### 7.4 商品详情

    生活账本
    把每天的收支，也放进生活的时间线

    [预览一] [预览二] [预览三]

    可以做什么
    • 手动记录收入与支出
    • 按日期、分类和商家查看
    • 搜索、统计、同步与 CSV 导出

    将在这些地方出现
    • 中央“＋”中的“记一笔”
    • 日历当天的收支摘要
    • 全局搜索

    数据与隐私
    • 账目保存位置
    • 票据图片处理方式
    • AI 会读取什么

    价格                    永久解锁

详情页必须包含：

- 当前已经包含的功能，不把路线图写成购买承诺；
- App 与网页支持情况；
- 最低版本；
- 数据与权限说明；
- 停用、下架或退款后已有数据怎样处理；
- 一次购买还是订阅；
- 恢复购买；
- 支持与退款帮助。

## 八、扩展类型与商业边界

| 类型 | 示例 | 推荐权益 | 不应混入 |
| --- | --- | --- | --- |
| 功能扩展 | 生活账本 | 一次取得、永久解锁 | Pro 到期后锁住已有数据 |
| 内容包 | 主题、贴纸、模板 | 单包永久拥有或明确的 Pro 内容库 | 模糊写“全部未来内容” |
| AI 操作 | 票据整理、智能分类 | 执行前明确鹿角消耗 | 手工录入、导出、纠错 |
| 持续服务 | 云端附件空间、持续生成服务 | Pro 或明确订阅 | 用户取回自己数据的权利 |

核心日历、待办、笔记、日记、提醒、同步和导出继续遵守现有免费承诺。扩展系统不能成为把核心能力重新拆散收费的工具。

## 九、技术架构：首期不是远程代码插件

### 9.1 决定

首期采用“模块化功能 + 统一权益 + 受控入口”：

- 功能实现随 App 或网页版本一起发布；
- 服务端目录决定商品展示和可用范围；
- 经过验证的权益决定用户能否启用；
- 扩展只能注册系统允许的入口和数据接口；
- 主题、贴纸等资源可以按需下载；
- 不下载并执行任意第三方原生代码、JavaScript 或 HTML 小程序。

这样可以减少供应链、远程执行、审核、隐私和版本兼容风险。未来如考虑可执行小程序，必须另立安全、审核、支付、权限和内容治理规格，不沿用首期扩展合同直接开放。

### 9.2 核心对象

#### ExtensionDefinition

扩展的稳定定义，至少包含：

| 字段 | 含义 |
| --- | --- |
| id | 永久稳定的语义 ID，例如 looka.finance |
| version | 扩展合同版本 |
| minAppVersion | 最低 App 或网页版本 |
| nameKey / descriptionKey | 多语言文案 key |
| icon | 官方资源标识 |
| category | 功能、内容、AI 或服务 |
| capabilities | 扩展可以调用的受控能力 |
| entryPoints | 在哪些系统位置出现 |
| permissions | 需要的权限和数据域 |
| platforms | Android、Web、未来 iOS 的支持情况 |
| dataSchemaVersion | 扩展数据迁移版本 |
| productIds | 各平台商品 ID |
| entitlementType | 永久、订阅、消耗型或免费 |
| dependencies / conflicts | 依赖与冲突 |
| privacySummary | 商店与启用前的隐私摘要 |
| status | 草稿、可售、下架或停止维护 |

#### ExtensionEntitlement

服务端权益记录至少包含：

- Looka 账号 ID；
- 扩展 ID；
- 平台商品 ID；
- 来源：Apple、未来 Google Play、Web、活动发放或历史迁移；
- 权益类型；
- 原始交易标识和当前交易标识；
- 购买或发放时间；
- 到期时间，仅订阅型使用；
- 当前状态：有效、待验证、退款、撤销或争议中；
- 幂等键；
- 最后验证时间。

客户端缓存只能用于离线体验，不能成为永久权益的唯一真源。

#### ExtensionInstallation

记录用户如何使用扩展：

- extensionId；
- enabled；
- 已启用版本；
- 启用时间；
- 平台；
- 入口排序与显示偏好；
- 本地资源版本；
- 最近迁移结果。

永久权益属于账号；入口排序可以因 Android 与网页布局不同而按平台保存。

#### CatalogOffer

商店报价与权益分离，至少包含：

- 扩展 ID；
- 平台；
- 商品 ID；
- 显示价格；
- 可售地区；
- 一次购买或订阅；
- 促销资格；
- 上下架状态；
- 购买页文案版本。

服务端不自行计算 Apple 等平台的展示价格；用户界面优先使用平台返回的本地化价格。

### 9.3 数据域

重要扩展数据不能全部塞进一个通用 JSON 字段：

- 生活账本使用独立 finance_ 或 money_ 实体；
- 金额使用最小货币单位整数与 ISO 4217 币种；
- 扩展数据具有独立 schemaVersion 和迁移；
- 同步层可以共享 envelope，但数据实体仍按领域区分；
- 删除账号、备份、恢复和导出必须枚举每个扩展数据域；
- 分析事件不记录账目金额、商家、票据文字或图片内容。

## 十一、生活账本作为首个功能扩展

### 11.1 定位

生活账本是“记录和回看生活”的自然延伸，不把 Looka 变成企业财务、报税或投资工具。

### 11.2 启用后的入口

1. 中央“＋”新增“记一笔”；
2. 日历当天详情显示收支摘要；
3. 全局搜索可查账目；
4. “我的扩展”可以打开完整账本、统计与设置；
5. 网页提供等价的高频创建入口，不能只把账本藏在“更多”。

不新增底部“记账”标签。只有真实使用频率证明它成为大量用户的稳定顶层任务后，才重新评估主导航。

### 11.3 首次启用

    永久解锁成功
    进入启用页
    选择默认货币
    查看数据与隐私摘要
    添加“记一笔”入口
    完成第一笔记录

购买成功后不强迫用户完成复杂分类、预算、账户和票据设置。

### 11.4 基础能力

永久权益包含：

- 手动记录收入和支出；
- 基础分类；
- 日期、商家、备注和币种；
- 日、月查看与基础统计；
- 搜索；
- Android 与网页同步；
- CSV 导入导出；
- 本地备份与恢复；
- 本机 OCR 文字识别。

以上能力不按次消耗鹿角。图片识别结果始终先成为草稿，用户确认后才能保存。

### 11.5 AI 能力

以下能力可以在真实成本和准确率验证后按次使用鹿角：

- OCR 文字整理为账目草稿；
- 智能分类；
- 多票据批量整理；
- 消费总结；
- 从用户主动选择的笔记生成导入草稿。

每次执行前显示消耗。失败、服务异常或没有生成有效草稿时自动退回；用户纠错、取消保存和手动修改不重复扣除。

## 十二、权益与支付合同

### 12.1 永久权益

生活账本采用永久权益，不属于 Pro 的临时租用能力：

- Free 与 Pro 用户取得的是同一套基础账本；
- Pro 到期不影响已取得权益；
- 涨价、重新安装或更换设备不要求原用户重复购买；
- 扩展下架后，已拥有用户仍可查看和导出已有数据；
- 用户主动删除数据与失去新建权限是两个不同操作。

### 12.2 平台结算适配

| 平台 | 目标方式 | 上线前条件 |
| --- | --- | --- |
| iOS | 非消耗型 App 内购买 | App Store Connect 商品、StoreKit、服务端交易验证、恢复购买 |
| Android | 按最终分发渠道的数字商品规则接入 | 单独核对 Google Play 或其他商店现行规则 |
| Web | 合规 Web 支付、活动权益或账号迁移 | 订单验证、退款、税务和客服合同 |
| 活动发放 | Promotional entitlement | 有来源、有效期和审计记录，不使用通用兑换码绕过平台结算 |

500 枚鹿角是否在某个平台作为可用取得方式，必须在该平台支付和虚拟货币规则核验后单独决定。未核验前，商店文案不显示“500 枚鹿角永久解锁”。

### 12.3 购买状态机

    not_owned
        └─ 发起购买 → purchasing
                          ├─ 用户取消 → not_owned
                          ├─ 平台待处理 → pending
                          ├─ 验证失败 → verification_required
                          └─ 验证成功 → owned_disabled
                                               └─ 启用 → enabled

退款或撤销进入 revoked。revoked 用户不能继续创建受限的新内容，但已有个人数据仍应允许查看、导出和删除。具体宽限与离线策略在支付实现前另行定案。

### 12.4 购买安全

- 客户端不自行授予永久权益；
- 服务端验证平台交易；
- 每次购买、恢复、退款和撤销都有幂等处理；
- 连续点击不会生成重复订单或重复扣款；
- verification_required 会后台重试并提供“重新验证”，不要求用户重复购买；
- 账号切换后立即重新核对权益，不能沿用上一账号的缓存；
- 日志保留交易状态，不记录完整支付凭证或敏感账目内容。

### 12.5 恢复购买

“恢复购买”放在商店底部和购买帮助中：

- 不在 App 每次启动时自动弹出；
- 用户主动触发；
- 恢复成功显示恢复了哪些扩展；
- 没有可恢复项目时给出明确结果；
- 恢复失败保留重试与客服凭证；
- 同一权益不重复收费。

## 十三、隐私、权限与数据生命周期

### 13.1 最小权限

- 扩展只能读取声明过的数据域；
- 启用扩展不等于同意 AI 读取全部数据；
- 日记 AI 授权不等于票据图片授权；
- 票据上传视觉模型必须单独说明；
- 不读取通知、短信、屏幕、无障碍服务、后台相册或未主动选择的剪贴板；
- 每个扩展详情都能看到它使用的数据和权限。

### 13.2 生命周期

| 操作 | 权益 | 数据 | 入口 |
| --- | --- | --- | --- |
| 停用扩展 | 保留 | 保留 | 隐藏高频入口 |
| 重新启用 | 保留 | 恢复可用 | 恢复入口 |
| Pro 到期 | 永久扩展不变 | 保留 | 不变 |
| 退款或撤销 | 进入撤销状态 | 可查看、导出和删除 | 停止新建，按合同显示说明 |
| 扩展下架 | 已拥有用户保留 | 保留 | 已拥有用户可管理 |
| 删除扩展数据 | 权益保留 | 按确认范围删除 | 入口可保留 |
| 删除账号 | 权益按平台规则处理 | 覆盖全部扩展数据域 | 清除 |

备份、恢复、账号注销、隐私导出和数据删除清单必须把扩展数据作为正式域，而不是只处理核心日历数据。

## 十四、视觉与交互规格

### 14.1 “更多”

- 使用安静的分组列表，不使用功能宫格；
- 页面背景为当前主题的浅色纸面；
- 账户卡是唯一允许轻卡片化的管理区；
- 行高建议 52–56 dp，Android 点击区至少 48 dp；
- 图标使用统一的线性图标，不以 emoji 充当全部功能图标；
- 分隔线从文字起点对齐；
- 分组标题小而克制，不增加装饰性编号；
- 不使用重阴影、高光玻璃、渐变描边或大面积商业插画；
- 支持大字体、屏幕阅读器、色觉差异和减少动态效果。

### 14.2 商店

商店可以比“更多”更有品牌表达，但仍保持：

- 一屏一个主要视觉焦点；
- 功能价值先于装饰；
- 真实截图先于抽象宣传；
- 价格与购买类型清晰；
- 所有购买按钮都说明结果；
- 所有商业状态不只依赖颜色；
- 不用弹跳、转盘、撒币或夸张庆祝诱导复购。

### 14.3 动效

- 行按压反馈约 80–120 ms；
- 页面前进与返回约 220–300 ms；
- 启用状态切换约 160–220 ms；
- 购买成功只使用一次短暂、克制的确认反馈；
- 系统开启“减少动态效果”时取消缩放、弹性和大范围位移。

## 十七、双端同步与验收

### 17.1 双端要求

任何用户可见扩展必须同时说明：

- Android 是否支持；
- 网页是否支持；
- 服务端是否同步；
- 不支持的一端显示什么；
- 从一端取得权益后另一端怎样恢复；
- 入口、文案和数据是否等价。

不能只在 Android 加“我的扩展”，却让网页继续以十七行旧列表承载全部入口。

### 17.2 关键验收

#### 更多与导航

- 根页分组、行顺序和摘要与规格一致；
- 返回恢复滚动锚点；
- 每个被移除的旧入口至少有一个已验证替代路径；
- 网页浏览器前进、后退和刷新不会丢失二级页状态；
- 商店故障不影响“更多”其他设置。

#### 扩展

- 未拥有、已拥有未启用、已启用、版本过低和下架五种状态都可复现；
- 停用不删除数据；
- 重新启用恢复原数据；
- Android 与网页对同一账号显示一致权益；
- 不支持平台展示兼容性说明。

#### 购买

- 用户取消、支付待处理、验证失败、重复点击、恢复购买、退款和账号切换全部测试；
- 服务端验证前客户端不授予永久权益；
- 购买后按钮从“永久解锁”变成“启用”或“打开”；
- 已购买用户不再次显示价格主按钮；
- 退款后已有数据仍可查看、导出和删除。

#### 生活账本

- 没有 AI 仍能手动记账、统计、搜索、同步和导出；
- 金额不使用浮点；
- OCR 与 AI 结果先成为草稿；
- 日历只显示摘要，不把每笔账当日程；
- AI 失败自动退回对应鹿角；
- 删除、备份、恢复和账号注销覆盖生活账本数据。

#### 可访问性

- 大字体下行高可增长，不截断价格和状态；
- 屏幕阅读器能读出名称、购买类型、价格和状态；
- 颜色不是唯一的状态表达；
- Android 点击区至少 48 dp；
- 减少动态效果开启后不使用弹性缩放。

真机或真实浏览器未验证的项目只能标记为“已实现待测”，不能标记完成。
