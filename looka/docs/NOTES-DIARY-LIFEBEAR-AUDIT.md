# Looka 笔记／日记页设计、功能与 Lifebear 对齐审查

> 文档状态：讨论稿，不代表已经进入开发或上线  
> 审查日期：2026-08-24  
> 审查范围：Android App、网页端、Looka 母档与计划书、Lifebear 官方公开说明  
> 核心原则：已确认 BUG、功能差距、设计建议和待验证风险必须分开记录

## 一、结论摘要

Looka 的笔记／日记页已经完成了大部分基础结构：搜索框置顶、笔记与日记分工、笔记清单、中央加号按当前页面创建、空状态和轻量视觉语言都已出现。Android 端的一级结构较接近 Lifebear，网页端仍有明显差距。

目前不能认定为“已经完整对齐 Lifebear”，主要原因不是页面不好看，而是以下行为尚未闭合：

1. Android 笔记的系统返回与顶部返回执行不同逻辑，存在未保存内容丢失风险。
2. 网页全局搜索读取了旧字段，搜不到笔记正文和日记正文。
3. 笔记和日记的草稿只保存部分字段，恢复条件也不完整。
4. Android 与网页的保存、取消和退出规则不同，用户需要学习两套行为。
5. 笔记清单只有创建和选择，缺少重命名、改色、删除和排序入口。
6. 日记缺少页内日期切换，笔记和日记均不支持图片附件。
7. 辅助文字对比度、触摸区域、网页键盘操作和语义标签仍需改善。

因此，当前更准确的判断是：

- **视觉结构：基本对齐。**
- **核心交互：部分对齐。**
- **数据安全与跨端一致性：尚未达标。**
- **Lifebear 完整功能能力：仍有缺口。**

## 四、已确认 BUG

### BUG-ND-001 · Android 笔记系统返回可能丢失未保存内容

**优先级：P0**  
**证据级别：L · 代码实证**

顶部返回按钮调用 `saveAndBack()`，会保存后退出；手机系统返回由导航栈直接处理，页面没有 `BackHandler`，因此不会经过同一保存逻辑。

现有草稿机制也无法完整兜底：

- 草稿只写入正文 `content`，不保存标题和 `listUid`。
- 已有笔记加载数据库正文后，只有数据库正文为空时才会恢复草稿，因此已有笔记的正文草稿通常不会恢复。
- 新建笔记只填写标题时，草稿实际写入空正文，标题无法恢复。
- 修改清单归属后被系统杀进程，清单变更无法恢复。

**代码位置：**

- `app/src/main/java/com/looka/app/ui/notes/NoteEditScreen.kt:64-89`
- `app/src/main/java/com/looka/app/ui/notes/NoteEditScreen.kt:95-105`

**影响：** 用户以为“笔记返回自动保存”，但同一个页面使用不同返回方式会得到不同结果，可能造成真实内容丢失。

**建议修复：**

1. 顶部返回、系统返回、返回手势和页面被导航替换时统一进入同一个退出合同。
2. 草稿保存 `title + content + listUid + updatedAt`，不要只存正文字符串。
3. 已有笔记和新建笔记使用同一套草稿恢复规则。
4. 保存成功后再清理草稿；保存失败时保留草稿并给出恢复提示。

**验收标准：** 四种退出路径结果一致；标题、正文和清单均可恢复；已有笔记的短改、长改和清空都不会被旧草稿覆盖。

### BUG-ND-002 · 网页全局搜索搜不到笔记正文和日记正文

**优先级：P0**  
**证据级别：L · 代码与实测双重确认**

网页“更多 → 搜索”读取：

- 笔记正文：`p.body`
- 日记正文：`p.body`

真实数据字段均为 `p.content`。因此全局搜索只能命中笔记标题，无法命中笔记正文，日记则整类无法命中。

本次实测：

- 笔记正文含“下周”，搜索“下周”显示“没有找到相关内容”。
- 日记正文含“散步”，搜索“散步”显示“没有找到相关内容”。

**代码位置：** `server/public/app.js:1752-1781`  
**计划书既有记录：** `docs/FEATURE-PLAN.md:8136-8148`

**建议修复：** 使用真实字段并统一搜索映射：日程 `title + memo`、任务 `title + memo`、笔记 `title + content`、日记 `content`。

**验收标准：** 标题、正文、备注分别建立测试数据，每个字段都可单独命中；无结果不能让用户误以为数据丢失。

### BUG-ND-003 · 日记草稿恢复会漏掉缩短、重写和清空内容

**优先级：P1**  
**证据级别：L · 代码实证**

日记草稿只有在“草稿长度大于已保存正文长度”时才恢复。以下情况可能被忽略：

- 把原文改短；
- 用更短的新内容完全重写；
- 清空正文；
- 只修改心情；
- 清空后旧的较长草稿仍残留。

**代码位置：** `app/src/main/java/com/looka/app/ui/notes/DiaryEditScreen.kt:78-96`

**建议修复：** 草稿保存正文、心情和时间戳；用“草稿更新时间是否晚于已保存记录”判断恢复，不使用文本长度判断。

**验收标准：** 长改、短改、清空、只改心情和杀进程恢复全部有明确结果，不恢复陈旧草稿。

### BUG-ND-004 · 网页编辑器误触遮罩会直接丢失内容

**优先级：P1**  
**证据级别：L · 代码与实测确认**

网页笔记和日记使用通用弹窗。点“取消”或点击弹窗外遮罩都会立即清空弹窗，没有 Dirty State、草稿或放弃确认。

**代码位置：**

- `server/public/app.js:355-361`
- `server/public/app.js:925-948`
- `server/public/app.js:968-993`

**建议修复：** 有改动时点击遮罩、取消或浏览器返回均进入同一退出合同。若采用自动保存，应明确显示“已保存”；若采用显式保存，应提供“继续编辑／放弃修改”。

**验收标准：** pristine 直接关闭；dirty 不会无提示消失；键盘 Escape、遮罩、取消和浏览器返回行为一致。

### BUG-ND-005 · “允许并继续”没有继续执行 AI 润色

**优先级：P2**  
**证据级别：L · 代码实证**

日记首次使用 AI 润色时，授权按钮写“允许并继续”，但点击后只保存权限并提示“再点一次 AI 润色”。

**代码位置：** `app/src/main/java/com/looka/app/ui/notes/DiaryEditScreen.kt:203-217`

**建议修复：** 授权成功后自动继续本次润色；如果不自动继续，按钮应改为“允许”。

## 五、功能缺口与产品建议

### GAP-ND-001 · 搜索不支持多个关键词

Android 和网页页面搜索都把整段输入作为一个连续字符串。输入“会议 下周”时，即使标题含“会议”、正文含“下周”，也无法命中。

**建议规则：** 按空格切成多个非空关键词，对标题和正文合并文本执行“所有关键词均命中”。第一阶段不需要复杂分词、拼音或语义搜索。

### GAP-ND-002 · 笔记清单生命周期不完整

当前两端都只能创建和选择清单。Android ViewModel 已有重命名和删除方法，但没有 UI 调用；排序也没有用户入口。

**建议第一阶段补齐：**

1. 重命名；
2. 改色；
3. 删除非默认清单；
4. 删除清单时把笔记迁回“我的笔记”，不删除笔记；
5. 清单排序。

### GAP-ND-003 · 日记页内不能切换日期

Android 可以从日历选中某天进入日记，但从日记页中央加号进入时只能打开今天；编辑器日期只是标题，不能点击更改。网页也只能接收外部传入日期。

**建议：** 日期标题可点击打开日期选择器；保存前如目标日期已有日记，应明确提示合并、替换或取消，不允许静默覆盖。

### GAP-ND-004 · 图片附件尚未实现

Lifebear 已公开提供笔记、日记图片能力；Looka 当前两端均未实现。对于“手帐产品”，照片、票根和生活记录具有核心价值，但图片同步涉及压缩、存储、配额、隐私和失败恢复，不建议只在 UI 上先放一个不可用入口。

**建议顺序：** 本地附件模型 → 图片压缩与缩略图 → R2／对象存储通道 → 离线队列与重试 → Free／Pro 存储额度 → 图片 AI 能力。

### GAP-ND-005 · 网页信息架构与 Android 不一致

Android 在“笔记”一级入口内切换笔记／日记；网页把笔记放在底部导航，把日记放进“更多”。这会让网页用户把日记理解为设置或次级功能。

**建议：** 网页“笔记”页也提供“笔记／日记”切换。桌面端可以保留更宽布局，但不应改变一级心智。

## 六、保存与草稿合同建议

当前文档体系存在一处需要统一的决策：V014 母档要求有明确 Save 的 Note dirty 关闭时显示放弃确认；Looka 后续计划则主动选择“笔记返回静默保存”。主动偏离本身可以成立，但当前代码只让顶部返回自动保存，系统返回不保存，因此实际行为既没有完整遵循 Lifebear，也没有完整落实 Looka 自己的选择。

建议冻结为以下 Looka 合同：

### 6.1 笔记

- 用户填写标题或正文后，所有退出路径都自动保存。
- “保存”按钮含义为“立即保存并返回”，不是唯一保存机会。
- 完全空白的新笔记不创建记录。
- 数据库保存失败时不清草稿、不退出，并给出重试提示。
- 标题、正文和清单归属共同进入草稿。

### 6.2 日记

- 保留显式“保存”，让用户明确什么内容成为当天日记。
- 返回时如有未保存修改，保留本地草稿并给出“已保存为草稿”的轻提示；也可以采用“保存／放弃／继续写”三动作，但不要无提示丢失。
- 日期、正文和心情共同进入草稿。
- 同一天仍只保留一篇正式日记。

### 6.3 网页

- 保存和草稿语义与 Android 一致。
- 点击遮罩、浏览器返回、Escape 和“取消”必须走同一个退出判断。
- 弹窗关闭后焦点回到原笔记或原日记行。

## 七、视觉、文案与无障碍

### 7.1 已经做对的部分

- 搜索框在页面顶部，用户打开页面即可搜索。
- 白底、大留白、浅灰分隔和弱卡片化符合“安静工具骨架”。
- 笔记标题、正文摘要、更新时间的层级清楚。
- 清单 chips 比下拉列表更适合高频切换。
- 空状态使用小鹿插画和明确创建引导，符合手帐产品的温度。
- 页面没有明显的模板化、Dashboard 化或过度装饰问题。

### 7.2 对比度问题

日期和部分提示使用 `#B9BBB9`：

- 白底对比度约 `1.93:1`；
- 浅色搜索底对比度约 `1.82:1`。

普通小号文字建议至少达到 `4.5:1`。当前 `#5C6670` 在白底约为 `5.85:1`，可作为现有设计体系内的安全替代。

参考：<https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html>

### 7.3 触摸区域与语义

- Android 心情按钮视觉与触摸区域均为 `30dp`，低于 Android 建议的 `48dp × 48dp`。
- 清单 chip 和“笔记／日记”切换的实际触摸高度偏小。
- 心情按钮没有可读名称、选中状态和单选组语义。
- 网页笔记／日记行使用带点击事件的 `div`，键盘无法可靠进入和触发。
- 网页弹窗缺少焦点锁定、Escape 关闭判断和关闭后的焦点恢复。

参考：<https://developer.android.com/guide/topics/ui/accessibility/apps>

### 7.4 中文文案建议

| 当前文案 | 建议文案 | 理由 |
|---|---|---|
| 搜索笔记名、正文 | 搜索标题或正文 | “笔记名”有日式直译感，“标题”更符合大陆用户习惯 |
| 10月4日(五) | 10月4日 周五 | 中文日期表达更自然 |
| 允许并继续 | 允许并继续处理 | 仅在授权后确实自动继续时使用；否则改为“允许” |
| 一天一页，从今天开始记录吧 | 一天一页，记下今天 | 更短，更像手帐产品 |

大陆主导航继续使用“笔记”，不建议直接改成“备忘录”。“备忘录”可作为首次说明中的辅助词，例如“记录备忘、灵感和资料”。

## 八、建议修复批次

本文只定义建议顺序，不代表已经授权开发，也不在 `docs/EXECUTION.md` 勾选状态。

### 批次 A · 数据安全与搜索正确性

1. 统一 Android 笔记所有返回路径。
2. 重做笔记和日记草稿结构与恢复判断。
3. 修复网页全局搜索字段。
4. 增加笔记／日记保存、返回和恢复测试。
5. 真机验证 Room v6→v7 覆盖安装迁移。

## 九、验收清单

### 9.1 Android 笔记

- 顶部返回、系统返回键和返回手势结果一致。
- 新建笔记只填标题，杀进程后可恢复。
- 已有笔记把正文改短，杀进程后可恢复正确版本。
- 修改正文和清单后进入创建清单弹窗，返回时内容完整。
- 保存失败不退出、不清草稿。
- 完全空白的新笔记不产生记录。

### 9.2 Android 日记

- 长改、短改、清空和只改心情都能正确恢复。
- 草稿不会覆盖更新时间更晚的正式日记。
- 首次允许 AI 日记权限后，本次操作行为与按钮文案一致。
- 心情按钮触摸区域达到 48dp，并能被 TalkBack 读出名称和选中状态。

### 9.3 网页

- 笔记标题、笔记正文和日记正文均可被全局搜索命中。
- “会议 下周”可命中两个词分布在标题和正文中的笔记。
- 编辑内容后点遮罩、取消、Escape 和浏览器返回不会静默丢失。
- 键盘可以进入并打开每一条笔记和日记。
- 日记与笔记位于同一一级入口，中央加号仍能按当前子页正确创建。

### 9.4 迁移与同步

- 在 v1.16.1 写入多条笔记、日记和任务，覆盖安装 v1.17.0 后数据一条不少。
- 旧笔记全部进入默认“我的笔记”清单。
- Android 新建、改名、排序和删除清单后，网页使用同一账号能得到一致结果。
- 离线修改后恢复网络，不出现重复清单、重复笔记或笔记丢失归属。

## 十、最终判断

当前笔记／日记页不需要推倒重做。搜索置顶、清单筛选、留白和列表层级已经形成正确骨架。下一步应优先补齐“写下来的内容不会丢、一定找得到、两端行为一致”这三件事，再扩展日期切换、清单管理和图片附件。

这比继续调整圆角、间距或装饰更重要，也更符合 Looka 作为手帐产品“日子有序，安心生活”的产品理念。
