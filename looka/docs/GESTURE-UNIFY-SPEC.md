## 三、我的异议（三条，请你拍板）

### 异议 1：删掉排序按钮会**丢功能**，两者不能互相替代

笔记那个「排序」不是手动排序，是**排序规则**：按更新日 / 按创建日 / 按笔记名。
长按拖拽给的是**手动顺序**。

- 删掉排序按钮 → 用户**再也不能"按名字排"或"按最近更新排"**
- 而且这个是**照 Lifebear 实机做的**（图 76：`並び替え` radio 三档）

**我的建议**：笔记页**保留**排序规则菜单，另外三处（分类管理等）的手动排序按钮删掉改长按拖拽。
如果你确认就是要全删，我照做，但这条要你明说。

### 异议 2：笔记和日记**没有 sortOrder 字段**，做不了手动拖拽

| 实体 | sortOrder |
|---|---|
| Task / TaskList / NoteList / Category | ✅ 有 |
| **Note** | ❌ **没有** |
| **Diary** | ❌ **没有**（日记按日期排，手动排序本身没意义） |

- 笔记要长按拖拽 → 得给 `Note` 加 `sortOrder` + **Room v9 迁移**
- 日记我建议**不做**手动排序：它天然按日期倒序，手动打乱反而找不到

### 异议 3：**左滑还是右滑？你两次说的不一样**

- 上一条你说：「**右滑**是可以删除的」
- 这一条你说：「**左滑**可删除」

我默认按 **左滑**（右手拇指从右往左划，是 iOS/Android 列表删除的通用方向）。
**如果你要的是右滑，说一声。**

### 4.2 技术上要小心的一件事

同一行上**同时**挂纵向拖拽（排序）和横向拖拽（删除），两个手势会互相抢事件。
必须先判断主方向再决定交给谁，否则会出现"想删却在排序""想排却划走了"。
这条我会做成**一个共享组件**，不在每个页面各写一遍 —— 你说的"不要有重复和冲突"就是指这个。

### 4.3 顺带必须一起做的

- **左滑删除必须配全局撤销条**。现在撤销条只挂在一个页面上，
  在别处左滑删了就没有撤销入口 —— 那比不做还糟。
- 网页端同步：网页现在完全没有拖拽和滑动，要补最基本的（长按拖拽在桌面端是拖放）。

## 五、崩溃：我查到哪一步，以及我还差什么

**已排除**（都实际读了代码，不是推测）：

| 怀疑 | 结论 |
|---|---|
| `tr()` 占位符格式化抛异常 | ❌ 排除 —— `tr` 是纯字符串 `replace`，不是 `String.format` |
| 笔记删清单和待办删清单写法不同 | ❌ 排除 —— 两处结构**完全一样**（同样的 ConfirmDialog + 异步删除 + popBackStack + null 守卫） |
| `ensureNoteListDefault` 插重复默认清单 | ❌ 排除 —— `byUid` 不过滤 deleted，不会重复插 |
| 服务端崩溃上报里有栈 | ❌ 库里只有 1 条 v1.9.0 的旧崩溃（padding 相关），不是这个 |

**我的最大嫌疑**（**是推测，没验证**）：

删除后 `nav.popBackStack()` 被调用**两次** —— 一次在确认按钮里直接调，
另一次是清单从数据流里消失后 `list == null` 守卫里的 `LaunchedEffect` 又调一次。
两次弹栈可能把导航栈弹过头。

**但同样的写法待办页也有，而待办删清单你没说崩溃**，所以这个解释不完整，我不当结论。
