## 二、🔴 必须修（阻塞级）

### R1 · 12/24 张资产烤进了残留文字，且是错位的别人的标题

**实测**（顶部 20% 区域深色不透明像素计数）：

| 文件 | 画面上出现的文字 | 应有内容 |
|---|---|---|
| `13_Checklist_Done.webp` | **「7. Coffee」** | 打勾清单 |
| `18_Music.webp` | **「12. Work Laptop」** | 听音乐 |
| `21_Eating.webp` | **「15. Shopping」** | 吃饭 |

受影响：**07 / 09 / 11 / 13 / 14 / 15 / 16 / 17 / 18 / 19 / 20 / 21，共 12 张**

**根因诊断**：标号偏移量恒定为 **−6**（13→7、18→12、21→15）。说明原图是一张**6 列的联系表（contact sheet）**，每格上方带编号标题；裁切窗口**整体下移了一行**，于是每张都把**正上方那一格的标题**带了进来。

**修法**（二选一）：
- [ ] 重新裁切：把裁切窗口上移一个标题条高度，或直接按主体外接框自动裁切
- [ ] 或让生成端**逐张单独出图**，不走联系表拼图（推荐，从根上避免）

**⚠️ 这条最值得注意的地方**：文档自己在 QC 里写了「禁止：图片文字 / 水印」，而首发 Demo 包**自己没通过自己的规则**。这正好证明——**QC 必须是自动执行的代码，不能是文档里的一句话**。

### R2 · 三份文档给出三套互相矛盾的 API 路径

| 来源 | 生成接口 |
|---|---|
| `Integration_Skill.md` | `POST /api/ai/theme-stamp/generate` |
| `skill_contract.json` | `POST /api/stamps/themes/generate` |
| `规划文档 v1.docx` | `POST /api/theme/assets/generate` |

- [ ] **统一为一套**。建议取 `skill_contract.json` 那套（`/api/stamps/...`），因为它层级最清晰且与现有 `/api/sync`、`/api/ai/chat` 风格一致
- [ ] 统一后把另外两份文档标注为「已废弃，见 skill_contract.json」

### R3 · 「stamp」一词在我们系统里已被占用，会撞车

| | 新文档的含义 | 我们代码里的含义 |
|---|---|---|
| `stamp` | **资产**（一张图） | **实例**（用户贴在某天的那一枚，`Entities.kt:180`，字段 `emoji / day / eventUid`） |

- [ ] 正名，避免实现时混淆：
  - 资产 → `stamp_asset`（图）
  - 用户贴的那一枚 → `stamp_placement`（实例）
- [ ] 现有 `Stamp` 实体需从 `emoji: String` 迁移到 `assetId: String`，并保留 emoji 兜底（老数据）

### R4 · 🚧 Cloudflare Worker 做不了抠图——整条流水线的技术死角

Skill 的 Step 2「Normalize Asset：Remove Background / Crop / Resize / WebP」，**在 Cloudflare Worker 上无法实现**：Worker 没有 Python、没有 rembg、没有 ImageMagick。

可选路径：

| 方案 | 抠图 | 裁切/缩放/转 WebP | 评价 |
|---|---|---|---|
| **让 gpt-image-1 直接出透明底** ⭐ | ✅ 原生 `background:transparent` | Worker 跑 photon WASM 即可 | **推荐：从源头消灭抠图需求** |
| Cloudflare Images | ❌ 不能抠图 | ✅ | 解决不了核心问题 |
| photon-rs WASM | ❌ 只能阈值抠色，边缘有白边锯齿 | ✅ | 会毁掉印章质感 |
| 外部抠图服务 | ✅ | ✅ | 多一个依赖 + 成本 + 故障点 |

- [ ] **定：绘图走 OpenRouter → gpt-image-1，要求原生透明底输出，Worker 只做 PNG→WebP 转换**
- [ ] 这也和之前的判断一致：国内模型（Kolors / FLUX）出不了透明底，不适合印章

### R5 · 额度冲突：一包 24 张 > Pro 每月 20 张

按现行定价，**Pro 用户一个月连一包都生成不出来**，免费版赠的 4 张更是一包都凑不齐。

- [ ] **改为按「包」计费**，与 theme pack 概念一致，也更符合用户心智（用户想的是"我要一套印章"，不是"我要 24 张图"）：

| 档位 | 建议 |
|---|---|
| 免费 | 体验 **1 包 ×6 枚**（迷你包） |
| Pro | **每月 2 包**（24 枚/包） |
| 终身 | 一次性 **10 包** |
| 加油包 | ¥6 = 2 包 ／ ¥18 = 8 包 |

- [ ] 配合「**先出 6 枚样张 → 满意再补齐 24 枚**」，不满意只浪费 1/4 的成本

## 三、⚠️ 需要你决策（会改变工作量）

### D-S1 · `position_x/y/scale/rotation` 是一次重大功能升级

新文档的 `calendar_stamp_instances` 带自由位置、缩放、旋转。**这意味着从「每天一个印章标记」变成「自由贴纸画布」**——影响月视图格子渲染、同步 payload、拖拽交互、撤销重做。

| | 现在 | 新文档 |
|---|---|---|
| 交互 | 点某天 → 选一枚 → 显示在格子里 | 拖拽 / 缩放 / 旋转 / 图层 |
| 工作量 | 已完成 | **约等于重做一个小编辑器** |

**建议：分两步。** 第三批先做「一天多枚 + 图片化」，自由画布放到第七批再评估。

### D-S2 · 主题范围被大幅扩展了

规划文档里，主题从「9 色色板」扩展到 **色彩系统 + 日历背景 + Sticker + Icon + 空状态插画 + Preview**。

- 好处：主题的感知价值和售价上限都高得多
- 代价：每套主题的生成成本、审核成本、适配成本都翻几倍；背景图还会影响文字可读性

**建议：主题分两级** —— `轻主题`（纯色板，AI 秒出，零绘图成本）/ `重主题`（含背景与插画，走绘图额度）。轻主题保证数量，重主题做精品。

### D-S3 · 风格一致性方案缺失

文档只用 `style: "LOOKA Cute Lifestyle Sticker"` 一个字符串锚定风格。**单靠 prompt 前缀，24 张必然飘。**

- [ ] 补 **reference image 锚定**：用已有的牛牛包 / 敦煌包 / 基础包做参考图
- [ ] 补 **样张确认环节**：先出 1 张 → 用户确认风格 → 该样张作为后续 23 张的参考图

### D-S4 · 官方首发包是「牛」，但品牌是「九色鹿」

Demo 包做得不错，但作为**官方首发包**用牛牛角色，和「可爱版九色鹿」的品牌主体不一致。

**建议**：牛牛包保留为趣味包，**另出一套九色鹿角色包作为官方第一包**（正好可以验证整条 AI 生成流水线）。

### D-S5 · 宠物照片生成贴纸 = 隐私敏感

规划文档提到「用户上传宠物照片 → 生成动作贴纸」。这涉及用户上传原始照片到第三方模型。

- [ ] 需要独立授权勾选 + 隐私政策条款 + 明确保留期限（建议：处理完即删原图）

## 四、与现有计划的衔接

| 新文档的阶段 | 并入我们的批次 |
|---|---|
| M1 静态包接入（Asset Library + Sticker Picker） | **第三批**（印章图片化） |
| M2 印章插入日历并保存 | **第三批**（一天多枚），自由画布 → 第七批 |
| M3 Theme API 服务化 | **第七批** |
| M4 AI Skill 异步任务 | **第七批** |
| M5 审核与发布 | **第七批** |

**结论：把 M1+M2 拆进第三批，M3–M5 留在第七批。** 这样官方包能早两批上线，AI 生成能力再逐步接上。
