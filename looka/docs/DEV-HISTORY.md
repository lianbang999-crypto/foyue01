## 一、这是个什么产品

**Looka · 可爱版九色鹿** —— 把日历、待办、笔记、日记和 AI 助手放在一起的生活手帐。

| 端 | 技术 |
|---|---|
| Android | Kotlin 2.0.21 · Compose M3 · Room 6（kapt，非 KSP）· minSdk 26 / target 35 |
| 网页 PWA | `looka.foyue.org` · Cloudflare Worker + D1 + R2 · 原生 JS 无框架 |
| AI | 小鹿 · Qwen（经硅基流动 .cn），Worker 中转，用户手机不直连模型厂商 |
| 分发 | R2 托管 APK + `version.json` 自更新，不走应用商店 |

设计参照 **Lifebear**（日本手帐类 App），采用 clean-room 方式：只从实机录屏和截图
提取交互语法与结构，不复制资产与代码。

## 三、这 8 天里最值钱的几次「错了又改」

工程价值不在做对的部分，在发现做错并改回来的部分。

### 1. AI 入口被两次「合理删除」删没了

§57 删掉更多页的 AI 行，理由是「顶栏已有」；§60 删掉顶栏按钮，理由是「更多页已有」。
两次都成立，合起来 AI 就从 App 里消失了。

**根因是流程缺陷不是手滑**：删入口时没有验证剩余可达路径。
→ 立为规矩：**删入口前先查全部可达路径，确认剩 ≥1 条**。

### 2. 「拖曳不灵敏」修错了两次

第一次以为缺反馈，加了震动 —— 治标。第二次母档给出实机结论：
Lifebear **没有长按前置**，直拖即移动。我们用的是 `detectDragGesturesAfterLongPress`，
必须先长按 500ms。**根因是手势语义，不是灵敏度参数。**

### 3. 菜单遮住贴纸，间隙调了两轮都没用

调 0.30 → 0.38 倍列宽都不管用。真因是**坐标系错位**：落点是窗口坐标（含状态栏），
而菜单画在被 Scaffold padding 下推的容器里，整体低了一个状态栏高度。
网格命中不受影响是因为它算的是差值，两边同源。

→ 教训：**参数调不动的时候，八成不是参数问题。**

### 4. 我读错了母档，造出一个盖住贴纸的气泡

§72 我从图里读出「绑定后印章上方浮灰色标题气泡」。三张实机图后来证明
Lifebear 月格里**只有贴纸**，名字在日详情行和编辑页表达。用户实测的
「保存后贴纸变成灰色的『嗯了』」就是这枚气泡。

→ 教训：**读图推断要标注为推断**，等到实机证据再升级为规格。
这也是后来母档引入 A/B/L/C/R 证据分级的由来。

### 5. grep 在大文件上说谎

复核网页文档时，`grep ANTLER server/src/worker.js` 返回 0 —— 我差点写下
「鹿角逻辑已被删除」。python 复验发现实际有 14 处。

→ 立为规矩：**结论性判断不单靠 grep，大文件用 python 复验。**

### 6. 「双重 Event」和「移动后残影」

保存日程后月历上同时出现金色事件条和灰色气泡；把贴纸拖走后原日期还留着一条。
两者同源：绑定关系读的是非响应式快照，且 `moveStamp` 只挪贴纸没挪日程。
详情页显示「日期已改」是假象 —— 它信的是传入参数，后台根本没改。

→ 教训：**UI 显示对了不等于数据对了。**

## 四、沉淀下来的工作方法

这套方法不是一开始设计的，是踩坑长出来的。已固化为 skill：
`.claude/skills/looka-dev/SKILL.md`。

### 六项准则（2026-08-24 用户定为价值观）

上一节六次「错了又改」，**没有一次是能力不够，全部是这六条里某一条失守**。
所以准则写在流程之前 —— 流程规矩都是它们的推论。

1. **诚实，不说谎** —— 做了就说做了，没做就说没做；不用确定语气说没查证过的话
2. **专心，专注，专一** —— 一次一批，做完验完再下一批
3. **精进，勤恳，不偷懒** —— `[x]` 只给实测通过的；不用不可靠工具走捷径
4. **不嫉妒，有耐心** —— 对其他智能体与大模型不嫉妒也不骄傲；谁发现的不重要，产品对不对才重要
5. **不贪婪，克制** —— 功能不因做得到就加，表达不用篇幅冒充深度
6. **不生气** —— 被纠正时先查证再回应，不辩解

全文见 skill 第零节。

| 原则 | 来处 |
|---|---|
| 计划先行：先写 §N 到计划书，再照着执行 | 用户：「写好计划照着走就不会有缺漏」 |
| `EXECUTION.md` 是唯一勾选处，`[x]` = 实测通过 | 避免「写完就算完」 |
| 每次改动 App 与网页同步 | 用户铁律 |
| 发版前必须先推 GitHub | §67 X12 |
| 母档证据分级 A/B/L/C/R，L 不能反向证明 B | v1.3 母档 |
| 没有实机图不下结论 | §62 我判错后立的 |
| 不开子智能体，主会话直做 | 用户铁律 |
| 让利于用户优先于商业条目 | 用户最高原则 |
