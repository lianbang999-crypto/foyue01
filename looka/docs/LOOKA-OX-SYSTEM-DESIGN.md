## 0. 一页总纲

**looka-ox 是什么**：一只懂你的 AI 小鹿住在你手帐里 —— 日历、待办、笔记、日记、贴纸
按各自最自然的方式存在，AI 不做"第 6 个模块"，而是成为**用户意图到结构化生活对象的桥**，
让捕获更少一步、整理更少一步、回忆更快一秒、手帐更像你自己。

**三个判断（本方案的根基）**：

1. **复刻的是机制，不是界面。** Lifebear 的成功链是
   `实用价值 → 频率 → 数据 → 记忆 → 身份情感 → 信任 → 增长`。
   界面可以像素级对齐，但 looka-ox 的胜负手是把这条链上每一环都用 AI 缩短。
2. **AI 最高原则：降低输入成本和理解成本，而不是增加一个"AI 模块"。**
   AI 应隐藏在 Context、Defaults、Template、Theme 之间（Product DNA §13）。
3. **先减摩擦 → 再做记忆 → 最后做 Agent。** 没有可靠底座，AI 只会放大错误
   （AI 战略母版 §37）。因此路线图严格按 Phase 0–5 推进，不跳级。

## 1. Lifebear 研究结论（我们到底学到了什么）

### 1.1 成功机制八条（战略母版 §01–§07）

| # | 机制 | looka-ox 的对应动作 |
|---|------|--------------------|
| 1 | 重新定义竞争：替代纸质手帐，不和日历 App 拼功能 | 定位为"个人生活容器"，北极星不是功能数 |
| 2 | All-in-one 但复杂性留在系统内部 | 五个一级入口 + 中央＋行为中心，首屏认知负担极轻 |
| 3 | 高频刚需驱动每日使用 | 计划—执行—记录—回顾闭环，任一行为都拉回产品 |
| 4 | 长期数据产生迁移成本 | 本地优先 + 云同步 + 可导出，数据是用户的 |
| 5 | 主题/贴纸/颜色 = 身份与情绪价值 | AI 主题引擎 + 印章生态作为一等产品层（见 §5.4） |
| 6 | 高满意度 → 自然增长 | 截图友好的月视图、分享卡、评分引导内建 |
| 7 | 把可靠性当产品价值 | 同步成功率、提醒自检、崩溃上报是 P0 不是运维 |
| 8 | 商业化与价值层级一致 | 免费工具价值 → 个性化付费 → 高级效率付费 |

### 1.2 Product DNA 十原则（复刻验收的宪法）

- **P1 Native-first, Date-projection second**：Event/Task/Note/Diary/Sticker 各有原生家园，
  Calendar 只是聚合投影层。**禁忌：不要做成一张带 type 字段的万能 Event 表。**
- **P2 Progressive disclosure**：默认界面短；父编辑器管理摘要，复杂规则进子编辑器。
- **P3 Context defaults**：从哪点＋，就带入什么（日期/时间段/List/模块）。
- **P4 Preference as speed**：稳定偏好变默认值；设置页是核心创建效率的一部分。
- **P5 Template as reusable intent**：模板保存"事情是什么"，Context 决定"何时发生"。
- **P6 Mental-model consistency > Form consistency**：共享 primitive，不共享万能表单。
- **P7 Calm Utility × Emotional Warmth**：白底、留白、弱边框的工具骨架 + 插画情绪层。
- **P8 Personalization is utility**：颜色/贴纸/主题承担识别、习惯与情绪三重功能。
- **P9 Global Create as action center**：中央＋是跨模块行为编排器（ContextComposer）。
- **P10 Commercial layer stays peripheral**：广告/订阅/商店不改变核心对象心智。

### 1.3 对象世界（数据模型的源头）

| 对象 | 原生组织 | 日期关系 | Calendar 角色 |
|---|---|---|---|
| Event | Calendar/Category | 必有日期 | 核心一等对象 |
| Task | List/Star/Label/完成态 | Due 可无 | 投影视图 |
| Note | List/搜索 | 无日期要求 | 默认不投影 |
| Diary | 日期+正文 | 日期是一等字段 | 生活记录层 |
| Sticker | Canvas/Sticker Set | 放置位置关联日期区域 | 视觉标记，可选绑 Event |
| External Event | 外部 provider | 外部决定 | Display Layer 来源 |

### 1.4 创建引擎速度公式

> 用户每次只填**变化量**：长期稳定的交给 Defaults，重复类型交给 Template，
> 当前日期/时间/List 交给 Context。**AI 的任务就是把"变化量"进一步压小。**

### 1.5 视觉与动效语言（已在 looka v1 冻结验证）

- 白底工具感：背景纯白、分隔线 0.6dp #ECECEC、主字 #1B1B1F、次级 #8A8F8E（AA 达标）；
  休日红 #E0504A / 周六蓝 #4A7DDC；品牌绿固定不随主题漂移。
- 时间轴像素冻结：小时 60dp、时间栏 46dp、日程块圆角 6dp 最小高 26 分钟、红色当前时间线。
- 动效全局 140–220ms 低装饰原则：月份方向滑动 220ms、页面转场右滑 1/5 屏 200ms、
  勾选弹簧 1.35→1.0、空状态 ±5dp 浮动。两端同参数同 key（i18n 单一真源）。
- 手势语法：贴纸**直拖即移动**（无长按前置）——这是用两次修错换来的语义级结论。

### 1.6 方法论资产（比任何单条结论都值钱）

- **证据分级 A/B/L/C/R**：A=官方确认，B=实机确认（冻结参考产品事实），L=我们自己当前实现，
  C=二者之间的实现决策。B 不能反向证明 L，读图推断必须标注为推断。
- **六项准则**（诚实/专一/精进/不嫉妒/克制/不生气）与流程规矩：
  删入口先验可达路径、`[x]`=实测通过、App 与网页同步改、参数调不动时怀疑坐标系。

## 2. looka-ox 产品定义

### 2.1 愿景与一句话

> **一只懂你的 AI 小鹿，帮你把生活安排好、记录好，也让生活变得更像你自己。**

演进路径：`Calendar → Digital Planner → AI Life Companion`。
looka-ox 直接按第三阶段设计架构，但按第一阶段的克制交付体验。

### 2.2 目标用户与差异化

| 维度 | 选择 | 理由 |
|---|---|---|
| 首发市场 | 中国大陆（简中优先），架构原生支持多语+海外路由 | 复用 looka 的硅基流动链路与 i18n 管线 |
| 人群 | 20–35 岁、喜欢手帐/贴纸/情绪记录的用户（与 Lifebear 日本用户画像同构） | 情绪价值付费意愿最高 |
| 差异化① | **AI 原生手帐**：AI 在每个模块内部减摩擦，不是聊天机器人挂件 | Lifebear 无此层；通用日历 App 也无 |
| 差异化② | **AI 主题/印章生态**：对话生成整套主题资产 + 个人宠物贴纸 | 已验证 ¥0.002/张的生图管线 |
| 差异化③ | 小鹿人格跨模型一致：换模型不换"鹿" | Memory/Persona 独立于 LLM |

### 2.3 产品原则（在 P1–P10 之上新增）

- **A1 AI 是桥，不是大厅**：任何 AI 能力必须落到既有对象（Event/Task/Note/Diary/Sticker/Theme），
  不新建"AI feed"式页面；聊天入口存在，但每次对话的出口是结构化动作。
- **A2 可解释、可撤销、可审阅、可控制记忆**：低风险默认执行、中风险执行后反馈+Undo、
  高风险预览+确认；提供"小鹿最近做了什么"活动记录；记忆可查/改/删/暂停。
- **A3 显式标识**：AI 生成内容遵守《人工智能生成合成内容标识办法》（2025-09 施行），
  生成的主题/印章/文本带元数据标识。
- **A4 双端同源**：App 与 Web 共享同一套对象 API、i18n key、动效参数与文案措辞。
- **A5 数据主权**：本地优先可离线全功能；导出永远免费；删除=真删（90 天墓碑仅用于同步）。

## 3. 信息架构与交互系统

### 3.1 Global Shell（五个一级入口 + 行为中心）

```
┌──────────────────────────────────────────┐
│ Calendar │ ToDo │ (＋) │ Note&Diary │ More │   ← 底栏 58dp
└──────────────────────────────────────────┘
```

中央＋ = **ContextComposer**：读取当前模块/日期/时间/List/选中态，
决定默认创建类型（Calendar→Event，ToDo→Task，Diary 日→Diary），
Calendar 内可切 Event / Task / Sticker / **说一句话**（AI Capture，见 §4.2）。

### 3.2 页面层级（继承 v1.3 母档验收过的层级）

- Calendar：月（连续滚动）/周/日时间轴 + 选中日面板 200dp + 视图切换 Bottom Sheet
- Event：父编辑器（摘要+跳转）→ 子编辑器（日历选择/通知/重复）；范围编辑三选 Dialog
- ToDo：List/星标/标签/未来7天/已完成；Task Detail 高频状态在本体
- Note & Diary：List 为原生容器、轻量编辑器、List 切换用阻断式 Dialog；
  Diary 以日期为原生主键，日详情常驻"写日记"邀请行
- More：账号/订阅/AI/主题/设置/数据维护/反馈/关于

### 3.3 贴纸画布系统

StickerAsset（素材）与 StickerInstance（放置实例：date、x/y、scale、rotation、event_ref）分离；
直拖手势、连续盖章、Popover 锚定、跨周落点、z-order——全部沿用 v1.14–v1.16 用血泪换来的规则，
规格以《Lifebear_Sticker_Canvas_Asset_Standard_v1.0》为准（256×256/WebP/透明底/一包≤48 枚）。

## 4. 小鹿 AI 系统

### 4.1 三种形态（缺一不可）

| 形态 | 风险 | 默认 | 判断标准 |
|---|---|---|---|
| **Invisible** | 低 | 默认开启 | 用户没注意到它 = 做对了。它不说话，只让字段自己填好 |
| **Copilot** | 中 | 出现条件全部满足才出现 | 一行内联建议或小气泡，先结论后动作，一键确认 |
| **Controlled Agent** | 高 | 必须授权 | 先预览再执行，执行后 Undo 是事务回滚 |

Copilot 出现的六个条件：有可执行价值、页面稳定且用户静止 900–1500ms、
不在滚动/拖拽/输入/picker/转场/键盘动画中、本页本次访问无其他主动层、
本会话主动建议 ≤2 次、未被用户关闭过（关过即 24h 冷却）。
Agent 三条硬规则：永远先预览、Undo 必须是事务回滚、删除/批量/对外行动需额外确认。

> 衡量标准只有一个：**每个关键动作比过去步骤更少、更懂上下文。**
> 加了 AI 之后步骤变多，这个 AI 就是失败的，不管它多聪明。

### 4.2 AI Capture（创建条第四段）

Global Shell 中央＋在 Calendar 内切出第四段「✨ AI」：说一句话或拍一张图，
800ms 内返回结构化草稿，**落回同一条创建条、复用同一套编辑器组件**——
不跳转、不换页、不进聊天室。用户点「改一下」就是普通编辑器，AI 只是帮他把字段填好了。

- 歧义处理：置信度不足时**只问缺的那一项**，不要自信地猜（「下周三」是 9月3日 还是 9月10日？）
- 图片输入：海报/截图/邀请函 → 提取时间地点人物 → 同样落回创建条
- 输出经 JSON Schema 验证 + 时区合法性校验后才成为草稿；落库永远是用户确认的动作

### 4.3 逐屏落点清单（开发时照着做）

| # | 落点 | 触发 | 形态 | 要点 |
|---|---|---|---|---|
| 1 | 时间语义解析 | 标题输入中 | Invisible | 「明天下午三点」自动填字段 |
| 2 | 分类建议 | 保存前 | Invisible | 按历史习惯预选，可改 |
| 3 | 冲突检测 | 时间确定后 | inline 提示 | 不弹窗；保存时升级为 Copilot 建议 |
| 4 | 今日注意力摘要 | 日历选中今天 | 信息区顶部一行 | 说哪件最重要、哪里有风险；不是「你今天有 7 件事」 |
| 5 | Event → Life Plan | 保存旅行/演出/考试等类型后 | Copilot 气泡 | 按事件类型 Playbook 拆准备清单，[全部添加][选几个][算了] |
| 6 | 日记润色 | 编辑页 ✨ 图标 | 需独立授权，默认关 | 保原意不改事实；续写给问句；**不做道德评价** |
| 7 | 生活回顾 | 21:30 / 周日 / 月末 / 年末 | Copilot 或卡片 | 年度回顾可导出可分享；不做强制分享 |
| 8 | 语义搜索 | 全局搜索框 | 直接回答 | 「上次看牙」命中「口腔科复诊」并给出日记佐证 |

医疗类事件**只做日程与准备支持，不做任何专业判断**。

### 4.4 AI Gateway 与模型路由

核心决策：**不绑定任何单一模型**。Persona/Memory 独立于 LLM 存在，换模型不换「鹿」。

```
客户端 ── 只认 looka 自有域名 ──► API / Account Service
                                    ├─ Region & Policy Resolver（区域与策略）
                                    ├─ Model Registry（能力档位：flash / reasoning / vision / embedding）
                                    ├─ Provider Adapter（硅基流动 .cn / OpenRouter / 未来自托管）
                                    └─ Observability（token、成本、延迟、错误率按用户/功能/Provider 维度）
```

- **区域路由红线**：不通过任何代理把官方未支持某地区的模型「转售」。中国大陆链路必须在
  完全不依赖受限 Provider 的情况下 100% 可用——直接继承 looka v1 已验证的
  硅基流动国内站 `.cn` 链路（国际站 `.com` 对 CF 出口有风控，勿改回）。
- **Fallback 不是随机换模型**：429/过载 → 同能力备用模型 + 指数退避 + 熔断；
  超时 → 同区域换 Provider 不跨政策边界；schema 非法 → 修复重试一次，仍失败降级为确认式对话；
  地区/策略拒绝 → **禁止绕行**。所有写操作带 idempotency key，防止重试重复创建。
- **验收标准**：默认模型从 A 换成 B 时，不需要修改 Calendar/Memory/Theme 业务代码，
  用户也不应感知「小鹿换了一个人」。做不到说明抽象层没建对。

### 4.5 长期记忆：四层架构

| 层 | 存什么 | 例子 | 生命周期 |
|---|---|---|---|
| **L0 业务事实** | 日历/待办真数据 | 周五 15:00 会议 | 业务规则决定 |
| **L1 Profile** | 稳定偏好、习惯 | 不喜欢早上开会 | 长期，直到修改/删除 |
| **L2 Episodic** | 值得保留的历史摘要 | 上月开始晨跑 | 可设 TTL / 重要度 |
| **L3 Semantic Index** | L1/L2 向量索引 | 检索「会议偏好」 | 随原记录同步删除 |

长期记忆**不是把全部聊天记录无限塞回上下文**。记录结构含 canonical_key、value、
original_text、confidence、importance、source（user_explicit/inferred）、consent_scope、expires_at。

写入规则：「以后/一般/我喜欢」→ 高优先级候选；一次性信息默认不转记忆；
敏感信息不自动永久保存；冲突时更新 canonical_key 当前值并留可审计版本；
「忘掉这件事」= 结构化记录 + 向量索引 + 缓存同步删除。

检索只给最小必要上下文：`merge(显式偏好, 语义检索 top_k=6, 近期高重要度30天, 当前业务事实)`。

**记忆必须可见可控**：更多 → 「小鹿记住了什么」，每条可 [改] [忘掉]，支持全部清空与暂停。
记忆的价值越大，隐私与控制的要求就越高。

### 4.6 工具调用契约

LLM 不能直接操作数据库，只能提出 Tool Call，业务服务校验后执行：

```
读：find_events / find_tasks / search_all / find_free_time / search_memory
写（全部需 idempotency_key）：create_event / update_event(scope: this|following|all) /
   delete_event / create_task / update_task / create_note / create_diary /
   place_sticker(asset_id, host_date, u, v) / apply_theme(需预览确认) /
   write_memory / forget_memory
```

安全边界：读/写分开授权；输出过 JSON Schema + 时区校验 + 权限校验；写操作返回稳定
resource_id（后续对话引用 ID，不让模型靠标题猜对象）；Tool 错误不暴露堆栈，
转成可恢复机器错误码。风险分级默认规则：低=自动执行，中=执行后反馈+撤销，
高=必须预览+明确确认。

### 4.7 小鹿人格

聪明但不卖弄 · 主动但不烦 · 温柔但不过度拟人 · 记得但不监视 · 建议但不命令 · 会做事而不是只会说。

✅「好，明天下午 6 点提醒你买牛奶。」
❌「购买牛奶是日常生活中的重要事项，合理规划采购时间有助于……」

禁止事项：不对生活做道德评价、不假装真实生命、不在无可执行价值时说话、
关闭后本会话不换个文案重弹。「小鹿的一天」（07:30 摘要 → 09:10 零确认建日程 →
11:40 冲突建议 → 21:30 一句记录邀请 → 周末整理 → 月末回顾）作为人格基准剧本，
两端同参数实现。

### 4.8 成本模型与额度

把 80% 流量留给便宜模型：普通对话/意图解析 ~80% 用 Flash 级，复杂规划 ~5% 用推理级，
图片理解/主题 ~10%，Embedding ~5%。控制优先级：先优化 Prompt 与记忆检索 >
默认低成本模型 > Provider 缓存 > 限制输出 token > 日/月预算告警。

面向用户的额度用具象单位（沿用 looka v1 的「鹿角」），免费用户每天有基础额度；
额度用完不是硬墙而是降级到 Invisible AI（时间解析仍可用）；**额度只对 AI 消耗收费，
不对手帐功能收费**。

## 5. 主题与资产生态

### 5.1 设计 token 与主题引擎

视觉骨架继承 looka v1 已冻结验证的参数：白底工具感、0.6dp #ECECEC 分隔线、
主字 #1B1B1F、次级 #8A8F8E、休日红 #E0504A / 周六蓝 #4A7DDC、品牌绿固定不随主题漂移。
主题只作用于**情绪层 token**（背景、点缀、插画），不动工具骨架——这是 P7 的工程化表达。

### 5.2 AI 主题生成管线

```
用户上传照片 → Vision 模型提取主色/光线/季节/质感/情绪 →
生成 2–3 个 Theme Spec（只是 token，不是图片）→ 预览卡片 →
真实日历背景实时预览 → [一键应用] 280–420ms crossfade → Snackbar「已应用 · 撤销」
```

铁律：视觉模型**只生成 Theme Spec，不直接改 UI**。可用颜色范围、对比度校验、
暗色模式兼容、回滚全部由 Theme Service 管理。生成结果按 A3 原则带 AI 生成元数据标识。

> 这是相对 Lifebear 的代际差异：Lifebear 是 Theme Store（大家买同一套），
> looka-ox 是 AI Theme Generator（每个人有自己独一无二、可持续变化的主题）。

### 5.3 分享卡与生活可视化

月视图截图友好是第一传播机制；月末统计卡、年度回顾故事卡可导出可分享，
产品名只是角落一个小标记。**让内容自然带出产品，不做强制分享、不做打卡。**

### 5.4 印章生态（一等产品层）

- **规格标准不可妥协**：256×256 / WebP / 透明底 / 一包 ≤48 枚；Asset 与 Instance 分离；
  直拖即移动、连续盖章、Popover 锚定、跨周落点、z-order 全部沿用 v1.14–v1.16 结论。
- **供给三来源**：① 内置包（继承 looka v1 的基础 42 + 敦煌 38 管线）；② 内容商店单买；
  ③ **AI 生成**：「让小鹿画一个」→ 透明底生图 → 标准化流水线：
  背景移除 → 512×512 标准画布 → 主体 bbox → 光学归一化 → 安全区校验 →
  日历真实尺寸预览 → 入库。生图成本沿用已定案的 OpenRouter `openai/gpt-5-image-mini`
  + `quality:low` 管线（实测 ¥0.002/张、真透明底）。
- **为什么不能跳过流水线**：某套贴纸因原图留白少就比别的大一倍，整个日历的视觉秩序就毁了。
  贴纸的可爱来自素材，贴纸的秩序来自标准。AI 只负责生成内容，Canvas 系统负责把它变成稳定的产品资产。
- **语义推荐**：打开印章抽屉时，当天有「咖啡」日程则咖啡章排前面（Invisible AI）。

## 6. 技术架构

### 6.1 客户端：Kotlin + Compose 原生 Android

核心竞争力恰好全落在原生强项上：闹钟级提醒（`setExactAndAllowWhileIdle` + 开机恢复 +
全屏闹钟 Activity）、Compose Canvas + `pointerInput` 的 1:1 跟手贴纸画布、
LazyColumn 连续月历。looka v1 的工程纪律直接继承：Room 用 kapt、R8 开启、
动效全局 140–220ms 同参数同 key、i18n 单一真源 `tr("中文")` 运行时字典。
Web 端（looka.foyue.org 经验）作为第二端，共享同一套对象 API 与文案措辞（A4）。

### 6.2 服务端：Cloudflare 全家桶起步

```
Workers API/BFF · R2(图片/主题/印章/APK) · KV(配置缓存) · Durable Objects(同步仲裁) · D1
```

- 数据库从第一天抽象数据访问层：D1 起步够快够省，但强关系数据长期看 PostgreSQL 更稳，
  抽象到位后迁移是换实现而不是改业务。
- **账号体系铁律**：`looka_users.id = lk_...` 永久主键，第三方登录只写 `user_identities`
  绑定表。任何第三方的 user id 都不得成为业务表主键。
- 可靠性是产品价值不是运维：同步成功率、提醒自检页、崩溃上报是 P0；
  Cron 清理过期会话/限流窗/墓碑（继承 v1 的每日任务模式）。

### 6.3 数据模型与同步

每个可同步实体带四公共字段：`uid / updatedAt(LWW 依据) / dirty / deleted(软删墓碑)`。
重复日程用 系列+规则+例外，不展开成 N 条。Diary 的 uid 固定为 `diary-<day>`，
两台设备同天各写一段天然合并为同一篇。同步协议 LWW，但**被覆盖版本必须写入
ConflictLog 且在「更多 → 同步冲突记录」可见可找回**——日记笔记是不可再生内容，
静默丢失不可接受。删除 = 用户侧真删，90 天墓碑仅用于同步收敛（A5）。

### 6.4 反馈与分析

诊断信息与截图**用户明确勾选**才上传，上传前可预览可删除；
日记、笔记、AI 对话正文默认不进入任何分析/日志/错误上报。
崩溃日志截尾防膨胀（v1 已验证的 Cron 做法）。

## 7. 商业化

| 层级 | 内容 | 说明 |
|---|---|---|
| **免费** | 手帐全部核心功能 + 本地使用 + 数据导出 | **无第三方广告**——手帐是私人空间 |
| **云同步** | 多设备同步、云备份 | 免费额度 + Pro |
| **Pro** | AI 额度提升、AI 主题/印章生成、高级语义搜索 | 订阅（鹿角体系） |
| **内容** | 主题包、印章包 | 单次购买 |

定价原则：核心手帐能力永远免费；锁的是有真实边际成本的消耗性资源（AI 调用、AI 生成、云存储）；
不用功能墙逼订阅；**数据导出永久免费，用户的生活数据不做人质**。
Lifebear 放 Premium 的子任务/标签/扩展搜索在 looka-ox 进免费层——
那是「管理生活」的基础能力，不是增值。

## 8. 路线图（Phase 0–5，不跳级）

顺序原则：**先减摩擦 → 再做记忆 → 最后做 Agent。**

### Phase 0 · 可靠底座（无 AI）

五对象完整 CRUD + 本地库 + 迁移；月/周/日三视图连续滚动；Event 父/子编辑器全链路；
提醒三件套（普通通知/闹钟级/开机恢复）+ 权限自检页；农历节气法定节假日调休；
贴纸画布完整状态机；设计 token + 主题引擎；导出 JSON/ICS/Markdown。
**验收：连续用两周不丢数据、不漏提醒、不卡顿。不达标不进 Phase 1。**

### Phase 1 · AI Capture

AI Gateway + Model Registry + Provider Adapter；创建条第四段一句话→结构化草稿→确认落库；
图片识别成事项；统一 Tool Schema + idempotency key。
北极星：从表达意图到事项落地的平均步骤数下降。

### Phase 2 · AI Copilot

冲突检测与解决建议；Event → Life Plan；今日注意力摘要；云同步 + 账号体系。

### Phase 3 · Life Memory

四层记忆落地；跨对象语义搜索；记忆管理界面（看得见改得动删得掉关得了）；周报/月报/年度回顾。

### Phase 4 · Personal Interface

照片→Theme Spec→预览→一键应用→可撤销；AI 印章生成 + 标准化入库流水线；可分享生活卡片。

### Phase 5 · Controlled Agent

跨多事项重排、周期管理、授权执行；「小鹿最近做了什么」活动记录。

## 9. 度量与信任

| 指标 | 验证的问题 |
|---|---|
| Activation（首 24h 完成 ≥1 个 AI 创建并保留） | AI 是否降低了第一次使用门槛 |
| **Capture Efficiency（意图→落地的步骤/时间）** | **AI 是否真的减少了操作** |
| Suggestion Acceptance（接受率+撤销率） | 建议是否有用、是否越界 |
| Memory Query Success（查询后无需二次搜索比例） | 记忆层是否真正可用 |
| Personalization Adoption（主题生成→应用转化） | 审美 AI 是否产生情绪价值 |
| **Trust Health（关闭 AI 率、撤销率、误操作率）** | **能力增长是否损伤了信任** |

最重要的两个是 Capture Efficiency 和 Trust Health。前者证明 AI 有用，后者证明 AI 没越界。
若前者上升而后者恶化，说明在用侵入换效率——那是错的。

**隐私底线（不可协商九条）**：按数据域独立授权（日记默认关）、拒绝即不静默越权、
私密正文不进日志、可解释（问时才展开）、可撤销、可审阅、可控制记忆、
置信度不足先问不猜、敏感领域克制。
